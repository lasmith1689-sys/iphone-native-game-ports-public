# One native worker authority: bounded support component

This self-authored component joins the checked native host/dispatcher, a retained pthread key service and a checked atomic DWORD increment through two thin adapters. The cookie worker-tag allocator is the sole linked worker-tag authority. The key-token counter remains a separate token domain.

The environment adapter reports the real host size, active host and dispatch depth. It cannot set depth or substitute a synthetic zero. The tag adapter forwards warm/read and preserves the existing status values. Existing production bodies and headers are unchanged.

The genuine Apple recipe requires Darwin ARM64, macOS SDK 27.1 and iPhone SDK 27.1. It builds ten production translation units plus two OWN fixture units, with no recovered engine, retail assets or signing material. The first native case links the independent old tag allocator as an explicit semantic negative: two live threads must expose the disagreement at the fixed owner assertion. Only then may the shared allocator pass. All controls are separate objects/binaries; production has no test fault providers.

The ten fixed positive modes cover 1,024 synthetic full-448-byte CPU increments, four real C setjmp fault discards, 96 foreign-thread refusals, actual get/set/NULL/replacement, 64 retained boxes, one-shot callback and clear/key-delete acknowledgement, owner exit and five explicit test-only uncertainty paths. Five controls must fail their exact fixture assertion with exit 4; arbitrary crash, timeout or nonzero exit is not acceptance. Expectations and the independent synthetic ISA vectors precede native output.

Preparation is on the actual main thread at dispatch depth zero. Initialization is on the real nonmain creating worker with the retained real host and depth zero. Allocate/get/set preserve their existing owner/phase gates at positive dispatch depth. LIVE retirement requires depth zero and clear, OWN callback, and key-delete acknowledgement; a CLOSED no-effect repeat can return at positive depth. The fixture does not reinterpret that repeat as a new retirement certificate. Foreign checks read the sole tag before mutable state and pthread ownership. No cancellation, dlclose, allocator reset, tag reuse or service destruction is allowed; published service, boxes and callback context remain valid to process exit. Destructor publication is bounded atomic-only and never calls a guest callback.

The recipe retains every selected raw object, dependency list, stack-usage report, Mac executable, link map, iPhone object pair, production archive and unsigned whole-cohort library, plus exact logs and reports. It checks selected tool/header bytes before and after, but does not copy SDK headers. Static local frame reports exclude callees and are not a whole-stack proof. Linked own definitions require unique object/map and file-backed code identities; hidden final n_type may be exactly 0x0e or 0x1e, never an external public definition. This is a selected finite visibility rule, not a claim about every possible linker.

The iPhone build is compile/link and metadata evidence only, minimum iOS 26 with SDK 27.1 and no code signature. Actual Mac pthread runtime is distinct from physical iPhone execution. No original source FLS API, source record, source callback, locale, heap, lock, engine initialization or game readiness is admitted. The synthetic native-entry table and four operand profiles are OWN fixture data, not game-host binding. No Objective-C, phone action, recovered source or retail metadata is included.

Run `python run_apple.py --output ../output` from an isolated materialized source directory on the selected genuine Apple host. Output must be fresh. The bounded public workflow authenticates the exact embedded source bytes, first-failure prefix and output closure; an uncertain child/capture produces wrapper-only failure reports and never claims descendant drain. There is no retry or expectation adjustment in the recipe.
