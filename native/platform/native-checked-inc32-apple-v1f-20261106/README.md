# Generic checked DWORD increment bridge

Self-authored support and explicitly synthetic tests. This package contains no application-derived functions, private address profile, data file, saved state, signing material or complete application. It is a finite component proof recipe; no application or phone readiness follows.

The bridge admits a retained creating nonmain pthread, fixed host/CPU identities and immutable copied descriptors before reading CPU state. Registration supplies valid, live, disjoint, naturally aligned atomic-compatible DWORDs and excludes native control storage. One checked seq-cst fetch-add returns the old DWORD; five INC flags are derived only after that RMW succeeds. CF and the other408CPU bytes remain unchanged. Missing authority, source mismatch or host failure cannot return fabricated success. Actor failure does not touch CPU; admitted source failure stamps the supplied source identifier and genuinely stops/discards through a real C landing pad. Partial effects are never rolled back or resumed.

The own CPU schema is448 bytes with8-byte alignment and compile-asserted field offsets. Only its types, checked64-bit stack read/pop and dispatch declarations are needed. The opaque binding's actual pthread_t remains private to its C implementation; callers query the compiled size/alignment and retain storage through process exit. A linked-once atomic saturating allocator gives each live worker its stable tag, with no wrap, reset or reuse. No clock-provider dependency is needed for the tag's depth refusal. No cancellation, dlclose, concurrent CPU mutation or source registration changes are admitted. Depth zero is an observed local lifecycle gate, not a certificate that every producer has drained.
